# first-draft-axi reference

Every flag and rule behind the commands in SKILL.md. Run `first-draft-axi --help` for the live list.


Run `first-draft-axi --help` for every command and flag. Each command prints JSON with a `help` list that says what to do next.

1. `first-draft-axi doctor` shows whether the user's model is ready, with no paid call.
2. No agent or model set: ask the user which BYOKit route and model to use. Never pick one for them.
   Then `first-draft-axi init --agent byokit:<route> --model <model>`. `doctor` lists the ready routes (`init` with no flags sets up the repo and the skill, not the model):
   their ready subscriptions first (`byokit:claude` for a Claude subscription, `byokit:codex` for ChatGPT, each through their installed, signed-in CLI), then plan-key or api-key routes. Claude models run only through `byokit:claude`; other routes refuse them. A key route reads its key from the environment variable `doctor` names; never save or print a key. `byokit:minimax:key` with no `--model` gets `MiniMax-M3.1-Flash-Preview`.
   Named visual comparisons (like Vercel, Apple-like, style of Linear, inspired by, similar to) in make/refine ask the user's own model to identify the reference, then check robots and linked public terms/licence before anonymous public capture at phone/desktop widths. Or pass `--like <brand-or-https-url>` explicitly. Plain `references "<prompt>"` only discovers an unverified candidate; add `--capture` to gather it. Unclear/restrictive permission refuses capture: never log in, bypass restrictions or silently replace the reference with an invented style. Scripts, frames and cross-origin assets are disabled; dynamic fidelity is bounded. Captures and source/permission/visual-language metadata are cached for 24h under the current project's `.first-draft/refs` (`--project` overrides root). Images plus observed type/spacing/colour/layout/CSS-motion brief go to generation; no source text/assets/pixels are copied into the design. The viewer shows references beside each option from its portable `.html.refs.json` sidecar; keep/copy it with the HTML. Refinement/posting preserve it. `--no-references` disables automatic gathering; local `--ref` still works. Model discovery/terms calls consume the configured model's normal quota, no paid reference APIs. Never describe candidate discovery alone as a captured reference.
3. `first-draft-axi make "<prompt>" --out <file.html> --options 3` makes the options (`--options` is 1 to 5, default 3; `--count` is an alias): `x.html` becomes `x-1.html` … `x-3.html`. Each option is one engine run of many model turns (at most 60), with the engine's own tools, design starters and skills. With Chrome or Chromium installed, the engine writes its JSX and each page is drawn into static, script-free HTML with its web fonts embedded; without one it writes that HTML itself. Each page is also rendered at 390px in light and dark and must fit the phone and have a dark theme (a dark-first style such as `--direction oled-neon` is checked to be dark by default instead) (`render_check` is `checked` or `skipped`). A failure is not retried; show the user the error.
   The look is the user's choice: `--direction <style-id>` gives every option one of 26 named styles (`first-draft-axi styles` lists them: editorial, oled-neon, bento, neobrutalism, glassmorphism …) and `--direction "<words>"` takes their own, for example a brand or a reference. With `--options` above 1 and no direction, each option takes a different style.
   Motion only when the user asks for it: put it in the prompt in their words ("a scroll story", "the ring slowly turning"). The engine's `motion-sites` skill then keeps one moving subject, still words, CSS-only motion whose first frame is the finished design, and a still under reduced motion; never add motion they did not ask for.
   Make controls (also in `make --help`):
   - `--options <n>` / `--count <n>`: integer 1–5, default 3; do not combine aliases.
   - `--direction <look>` / `--style <look>`: nonempty named style or free-text direction for all options; otherwise options vary. Do not combine aliases.
   - `--screens <names>`: 1–12 comma-separated screen/page names, each 1–100 characters; asks for every screen, distinct ids and navigation. Default: infer from brief.
   - `--brief-file <file>`: append nonempty UTF-8 text up to 100 KB; prompt may be omitted. Does not fetch URLs or images.
   - `--model <id>`: override the configured model for this run on the same BYOKit route; saved config is unchanged. Provider validates availability.
   - `--out <file.html>`: required unless using `--out-dir`; multiple options add `-1`, etc., or replace every `{i}` with its number. A single option keeps the file name.
   - `--out-dir <folder>`: alternative to `--out`, writes `option-1.html`, etc.
   Empty/invalid values, conflicting aliases and unreadable briefs fail before generation. Style and screen coverage are model instructions, not guarantees. Responsive 390px/1280px and light/dark remain the export defaults (dark-first styles stay dark); no theme, size, numeric seed or variation-strength flags.
   To change the option the user picked, run `first-draft-axi refine <option.html> "<their change>" --out <new.html>`: it starts from that option's HTML and writes a new option file (the original stays). Keep the change short; one engine run, not retried.
   Assets are optional and off by default (`--no-assets`). `first-draft-axi assets` detects installed providers without spending. For generated pictures, illustrations, icons, hero images or backgrounds, run the same make command with `--assets codex|higgsfield|codex,higgsfield|auto` first: it previews each provider's per-image cost and the ceiling (3 images per option) and exits without image or design model calls. `auto` offers every ready provider. Show the user the preview and obtain explicit approval before repeating with `--allow-asset-spend`; never add this flag yourself without approval. The design agent then decides which pictures the design needs and which approved provider makes each (engine tool `generate_image_asset`); the make JSON lists each option's `images` with provider, purpose and prompt. Higgsfield uses Z Image and previews live credits. Codex uses its signed-in CLI via BYOKit's installed account path, native image generation through `codex exec`, GPT-6 Luna and low effort; quota/overage cost is unknown, not free, and tool availability varies. Needs `codex login` or `higgsfield auth login`, plus ImageMagick 7 (`magick`). A mise shim without a runtime needs `mise exec node@26.1.0 -- first-draft-axi …` with the installed Node version. Never copy or inspect login files, print keys, or enable asset spending in CI. Assets are optimized WebP files beside the output and embedded into the actual screens, never a separate sheet. No host retries; failed designs can leave paid assets on disk. `refine` preserves embedded assets but generates none; `redesign` does not generate images.
   For a logo, run `first-draft-axi logo "<brief>" --out <file.html> --options 3` (needs Chrome or Chromium and a model that takes images; `--direction <kind>` from `first-draft-axi styles --logo` or the user's own words, `--ref <image>` for the user's own reference images (up to 6), `--explore auto|none|codex|higgsfield` (default auto: an image of each concept from a ready image provider, Codex on the user's subscription first, is redrawn as SVG; none, CI or no provider draws from the idea alone) and `--model` as in make; no `--like`, assets or fonts). The options are drawn three at a time, each concept has its own palette, and when the critic drops every drawn mark one second round runs from its advice (`rounds`, `second_round`, `exploration` and `timing` in the JSON). It first explores nine rough concepts in three territories at once (wordmark-led, abstract, symbol), each a metaphor from the brief or the product's story (never the name's initials), a base shape of its own, a one-line idea and a rough sketch; the same model critiques each territory's sketches drawn large and at 32 and 16 px, the host measures whether each sketch's detail survives at 16 px, and the strongest are refined into the options: with two or more, a wordmark-led and an abstract one among them, never two of one base shape. Only a plausible misreading, a cliche, a plain letter, a likeness to a reference or detail lost at 16 px overrides a keep, and without those a mark is a keep only at 9 or more out of 10 side by side with the best products of its class (Linear, Stripe, Vercel, Notion, Raycast) and the baseline (the plain output of the same model on the same brief, in `<file>.baseline/`; `baseline` in the JSON), with the reasons in `compared`, and under 9 it goes back for another round; an initial dressed as an object (a U as a cup) is dropped unless the brief asks for a letter (`kinds_missing` in the JSON when a required kind did not survive). Each finished mark is critiqued again, in at most two engine runs: redone once, or dropped for a reserve concept of its kind, drawn once; when neither passes, the best attempt is still the option, with `passed: false` and the critic's notes in its sheet and `logo.json` (tell the user), and the other attempts stay in `<file>-N.dropped/` (the JSON's `dropped` says why). The critic works from written principles and the user's `--ref` images only: logo never fetches or captures an inspiration site (logosystem, logofolio, branition, logoinspo, logotouse, iconly, fontinlogo, logobook are for the user to browse by hand). Each option is a brand sheet `<file>-N.html` (its one-line idea and its palette with reason and contrast, written in by the host) plus `<file>-N.logo/`: mark, wordmark and horizontal and stacked lockups as SVG, each with a `-dark` twin, `icon.svg`, `palette.json` (primary, accent, neutral, dark counterparts, reason), the icon as PNG at 16-1024 px, `favicon.ico`, `concepts.png` and `critique.png` (what the critic saw) and `logo.json` (concept, every explored concept with its verdict, critique, palette, files, check results). The host refuses SVG with text, images, filters, script or outside links, a non-square mark or icon, an icon outside its safe zone, unreadable at 16 px or losing a part, gap or cut at 16 px, palette colours under 3:1 or not the ones drawn, and light or dark files under 3:1 on their tile; the model fixes each finding before the option is written. `refine` and the Studio brief on a logo option start from its logo files and write a new `.logo/` folder (no new critique). Read `<design>.comments.json` before refining. Marks are model-drawn, the critique is the same model judging its own work, and the files are not trademark clearance: say so when you hand them over.
4. To show them, run `first-draft-axi view <the --out path>` in the background and give the user the printed url (default port 4430, on the tailnet address). It has a grid, a canvas per option with desktop (1280) and phone (390) side by side (or one of them), Fullscreen, and Play, which clicks through the option's screens. `<url>#/o/<n>/play` opens one option in Play.
5. People add comments in the view (Comment, then tap the spot); they are saved to `<design>.comments.json` next to the design and show as numbered pins: `[{"option": 1, "device": "phone", "x": 0.4, "y": 0.2, "text": "..."}]`, `x` and `y` as fractions of the frame, `device` optional. Read that file to see what people asked for before you refine.
6. To get the user's pick on a sign-off board (optional, needs `sign-off-axi`):
   `first-draft-axi post <the --out path> --title "<question>" --recommend a --option a=<label> --option b=<label> ...`.
   It copies the options into the board's `mocks/`, starts the view if needed, and each option gets a tappable Open link to its Play url under its mock (needs `sign-off-axi` 0.5.0+; the card text names each option's canvas url, phone and desktop side by side, as a fallback; the one-device Play urls are in the command's JSON). Pick `--recommend` yourself; a key already on the board needs a new `--key`.
   Journeys, tests and demos never ask the owner for a pick: post with `--evidence --media shot.png` instead of `--recommend` (an Evidence card with the options and Play links, no Decide card).
