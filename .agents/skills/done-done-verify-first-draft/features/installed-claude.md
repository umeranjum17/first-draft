1. Run `node --test test/claude.test.mjs`. It uses a private native CLI fixture and isolated HOME/XDG/TMPDIR: init, no-paid doctor, make, refine, missing executable and signed-out/API-key/other billing refusals. It exercises the published BYOKit adapters, not a replacement adapter. No paid calls in tests. Setup lists ready Claude then ChatGPT subscriptions with exact one-line init commands. Claude/Anthropic/Opus/Sonnet/Haiku ids outside byokit:claude are refused at init/doctor/make/refine, even with stale config; refused init preserves config. API-key, Bedrock and Vertex sign-ins never generate. The same journey sends PNG/JPG/WebP references as native image blocks on every turn and rejects malformed, oversized, excessive or unsupported inputs before spending. ImageMagick must be installed (CI installs it). References are not embedded.
2. Run `node --test test/model-pool.test.mjs` for the optional account pool: it drives the real CLI and published BYOKit adapters with stand-in `claude`/`codex` CLIs and a fixture pool helper. It covers quota rotation, provider/model-changing pick refusal, clean no-engine refusal, default routing without a helper, and credential redaction. No model, key or network.
3. For an explicitly authorized live proof, use a task-owned `FIRST_DRAFT_HOME`, but retain the normal HOME and the installed, already signed-in Claude binary. Never read, copy or override its login files, account pins, or keys. Run `node src/cli.mjs init --agent byokit:claude --model claude-opus-5-5` then `node src/cli.mjs doctor`. Save JSON: ready true, installed CLI, model availability not probed. Doctor only asks the native CLI for sign-in metadata; it does not call a model.
4. Run one bounded `node src/cli.mjs make "<small two-screen brief>" --options 1 --ref <task-owned image.png> --out <evidence>/notes.html`. Save stdout/stderr and exit code. Success requires the chosen generator and independent judge engines/models in stdout, a verified exported file and no truncation. Do not enable extra credits. On a Claude limit, report it and stop, not a fallback key or another provider.
5. For the reference proof, start `node src/cli.mjs view <evidence>/notes.html --host 127.0.0.1 --port <private-port>`. Use chrome-devtools-axi with a task-named session and explicit `newpage <url>` / `pages` / `selectpage <id>`, not element refs. For each fresh page, emulate light/dark then re-set the full viewport (390x844 or 1280x800) before capture. If the overlay resets a screen hash, open the exported file URL with the screen id hash instead. Capture both screens in each width/theme. Inspect every retained screenshot and verify PNG dimensions. Stop your view and browser.

## Boundaries

BYOKit owns account launch and structured Claude generation. Environment key names are filtered before reading values; no copied sign-in or account-pin changes. The adapter disables tools/MCP/hooks/session persistence and independently verifies subscription authentication. Claude-family ids are allowed only on `byokit:claude`; the refusal is `Claude models use your Claude subscription only. Run: first-draft-axi init --agent byokit:claude --model <model>`. No gateway/key fallback. Doctor resolves and names a ready authenticated source even without saved configuration. An unusable preference is not authentication; if no supported engine is usable, the normal CLI refuses with one provider-specific sign-in command. Generation and judging never share an engine, including subscription/API aliases.

`make/refine --ref` accepts local PNG/JPG/WebP, up to six, 5 MB each, 10 MB total, 4096x4096 maximum. ImageMagick validates/normalizes the first frame to PNG (magick or convert); doctor reports conversion availability and route capability. Unsupported routes refuse images explicitly. References are not offered to the asset embedder; reference-guided briefs disable automatic project-media embedding. The render gate now checks the whole file and each screen at 390x844 and 1280x800 in both themes; see the render-check feature.
