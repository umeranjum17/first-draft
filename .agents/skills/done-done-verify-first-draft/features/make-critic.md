# The independent critic and local reference library

Sources: `src/critic.mjs`, `src/judge.mjs`, `src/reference-library.mjs`, `src/reference-library.json`, `src/reference-capture.mjs`, `src/reference-network.mjs`, `src/cli.mjs`, `src/render-check.mjs`, `test/critic.test.mjs`, `journeys/critic.mjs`.

## User path

`first-draft-axi refs list` lists sources and local capture status. `refs pull` fills `$FIRST_DRAFT_HOME/refs-library`: anonymous public GETs, robots respected, scripts/cookies/interaction disabled, explicit licence quote checked, PNG hashes/dates/source URLs retained. The package contains the manifest, not third-party pixels. Unclear permission or a capture failure leaves notes and a link, with the reason. Notes and app kinds currently have no admitted default pixels; dashboard is light only (scripted chart omitted); landing/docs have usable permitted references. Never relabel a marketing page, incomplete theme or absent chart as a working app.

`make "<brief>" --out option.html` scores each option **once** beside a plain one-prompt page. References of exactly the same page kind enable a different subscription model: default `byokit:codex / gpt-6.1-sol`. `init --agent <generator> --model <model> --judge byokit:codex --judge-model <model>` can configure it; same-model and API-key judges are refused. Missing/corrupt references, unavailable subscription or failed independent response fall back to explicitly labelled generator self-assessment. `made.critic.judge` records the route/model/references or the fallback reason; `critique` records score, baseline score, seven axes with reasons for independent results, runtime and provenance. Low scores stay flagged without revision. `--no-critic` scores nothing.

`first-draft-axi judge option.html "<brief>" --plain baseline.html` drives the same critic on retained pages without generating or modifying either. Its generator identity is the user's saved config, not independently inferred from the input file: retain the original make JSON alongside a live report.

**What a judgement sees.** By default the critic sees the whole option and the whole plain page: full page height, light and dark, at 1280 and 390, tiled at most 1500 px per image and at most three tiles per view (a page past about 7500 px is scaled down to 60%, then cut, and the prompt says so). The prompt labels every image, the review names per view what it judged (`critique.views`), and the capture set is recorded in `critique.capture` (`mode`, `images`, one entry per image) so a score can be audited. `--first-view` (on `make` and `judge`) restores the cheap look: light only, the top 800 px, four images. Proof: `node --test test/critic.test.mjs` (capture set of a tall page, the tile cap, a short page not tiled, `--first-view`, the recorded capture set; no model call), and the same capture on a real page: `renderCheck().views(html)` from `src/render-check.mjs`, then read the images.

## Drive and evidence

1. Nonpaid integration: `node --test test/critic.test.mjs` drives the real CLI, Chrome and published BYOKit account/generation adapters with local stand-ins. It covers licence/robots refusal, phone/desktop light/dark fixture captures, the whole-page capture set (every view in light and dark at 1280 and 390, tiled when tall) plus the two references as native image attachments to a different judge, seven axes, one review without revision, --no-critic, retained-page immutability, missing route, failed judge, same model, forbidden key route, mismatched kind and modified cache. Browser discovery must ignore non-executable files and directories on PATH.
2. Nonpaid exact-clean-head capture: `done-done run critic`. The real CLI pulls task-owned fixture references, makes one option, judges it through the installed Codex protocol stand-in, and demonstrates the signed-out fallback. `critic-board.png` is the whole option/reference board at both widths with synthetic scores, route, runtime, axes and fallback. `make.json`, `fallback.json`, `refs.json` and `steps.json` retain the commands' outcomes. These prove protocol behaviour, **not design quality**.
3. Live (only when the task authorizes subscription use): pull permitted references, then judge ONE retained real output and its retained baseline using the command above. Retain original generator model/run duration, source hashes, judge JSON/model/duration, source licence dates and a rendered side-by-side report at phone 390 and desktop 1280. Disclose that report screenshots are fresh renders of the same retained source, not archived copies of the temporary model attachments. The score covers the first viewport only. Uncaptured brands are notes, not pixels; do not claim visual parity with them.
4. Look at every capture; stop only the processes you started. No public README/landing sample without the owner's score/review gate.

Before the critic, the default make still measures the drawn page and can repair host-measured defects once (`repaired`, or `unrepaired`/`repair_failed`). That is separate from the single critic pass. Proof: `node --test --test-name-pattern="strong grid" test/make.test.mjs`.

For a landing, home, marketing, product or company brief the same review also answers `ai_side` and the nine `hero` points (`critique.ai_side`, `critique.hero`), and a page that reads as the AI side does not pass: `node --test test/critic.test.mjs` (the landing tests) and `done-done run human-side-recapture` (`journeys/human-side.mjs`: `findings.json`, `make.json`, `human-side-board.png`, `steps.json`, a stand-in model).
