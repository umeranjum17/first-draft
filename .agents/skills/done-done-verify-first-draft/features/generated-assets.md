# Generated assets inside a draft screen

Entry: `src/cli.mjs make`, `src/assets.mjs`, `src/make.mjs`, `src/media.mjs`.

## Drive

`first-draft-axi assets` checks the existing providers without spending. `make "<brief>" --out screen.html --assets codex|higgsfield|codex,higgsfield|auto` prints each provider's per-image cost and the ceiling (3 images per option) and exits without a model call. Default/no-assets must generate no pictures; conflicting flags fail; `auto` offers every ready provider; `redesign --assets` is refused. Never read or copy credentials. Codex is BYOKit's installed CLI account, Higgsfield uses its normal login. Missing tools or login must show the actual setup cause. A mise shim without a runtime needs `mise exec node@26.1.0 -- first-draft-axi …` (or node 26.1.0's bin first on PATH) using the installed Node version.

With `--allow-asset-spend` the design agent gets the engine's own `generate_image_asset` tool; make offers it a `provider` field (the approved providers, each with what it is good at) at the model boundary and matches the choice back by prompt. The agent decides whether, what and with which provider; the brief never names a provider. The make JSON lists each option's `images` (provider, purpose, prompt, path, file) and `images_refused` (calls that made no image, e.g. the engine's plan-first gate or an unapproved provider: no spend). `done` fails while a generated image is not shown in an `<img>`.

Paid journey `assets` (spending approval required; `done-done run` refuses it, so `done-done verify assets --outcome "…"` and approve the spend gate, or drive `mise exec node@26.1.0 -- node journeys/assets.mjs` with `DONE_DONE_EVIDENCE_ROOT`; the design agent defaults to `byokit:codex` / `gpt-6.1-sol` and `FD_DESIGN_AGENT`/`FD_DESIGN_MODEL` override it): fresh First Draft config, cost preview, then one plant-shop page whose brief asks for a real-looking photo and a hand-drawn illustration. Codex: native image generation via `codex exec`, GPT-6 Luna, low effort; the native tool keeps its image in Codex's generated_images/<thread-id> cache and cannot save elsewhere (asking it to save made it call the tool twice), so the adapter imports the newest exec-UUID.png of that invocation's own thread only (the original is preserved); never follow a model-suggested path. Higgsfield: Z Image at the agent's aspect ratio, live credit quote. No host retry.

Proven live 2026-10-24 (Opus 5.5 via `byokit:claude`): the agent chose Higgsfield for the hero photo of the shop window and Codex for the monstera illustration, both embedded; exactly one Higgsfield job (0.15 credits) and one Codex image were spent.

## Assert and capture

The real output folder contains optimized WebP (metadata stripped, max 1024×1024, quality 80, max 800 KB). Generated HTML contains loaded, visible embedded data:image/webp images **inside their screens**, not a separate asset sheet. Viewing needs no network or sidecar file. The journey checks decode/visibility/no sideways scroll on the raw HTML (support `metrics.json`), then captures the real viewer: `first-draft-axi view` on 127.0.0.1 and a private port, `?screen=<id>#/o/1` for each data-oc-screen holding a generated image, at 390 and 1280 in light and dark, named `viewer-<screen>-<width>-<theme>.png`, plus steps.json (which names the providers the agent chose). Cost preview, make JSON, HTML, assets and metrics go in the sibling `<run-id>-support` folder: preflight must not be judged as if it were the generated result. The nonpaid `assets-recapture` run (`FD_ASSET_SOURCE=<retained make output> done-done run assets-recapture`) renders fresh captures of that output and hashes it, never regenerates; it reads the agent's choices from the retained `make.json` beside the source. Open every screenshot and check image placement, unclipped copy and no overlap. No motion changed, so no recording required. `refine` preserves the embedded images without generating another. CI must refuse asset spending even with the approval flag. ## Hero video

With the loop asked for (`--hero-video` beside any approved picture provider, or Higgsfield itself among the approved providers), the run makes one short silent loop from the still the design placed in its `data-section="hero"` (one per option, never regenerated from scratch): `generate cost seedance_2_0_mini --duration 5 --resolution 720p`, quoted in the same `--assets` preview as `video` with `max_videos`, then `generate create seedance_2_0_mini --start-image <still> --end-image <still> --generate_audio false --wait` so the loop is silent and returns to its first frame in the one blocking call. Same approval flag, same ceiling, no host retry, refused in CI, FFmpeg checked before the paid call. `--assets codex --hero-video` keeps the stills on the free Codex path and offers Higgsfield for the video alone, so no Higgsfield image credit is ever at risk. The loop is encoded (at most 1280 wide, no audio, faststart, at most 1.2 MB) to `<name>.assets-*/hero-loop.mp4` beside the still and embedded as a `data:video/mp4` URI; the host replaces that one hero `<img>` with `<video data-hero-loop autoplay muted loop playsinline poster="…">` plus the still (`data-hero-loop-still`), and adds a `prefers-reduced-motion` rule that hides the video and shows the still. The make JSON lists it under `videos` (provider, model, path, file, credits, still).

Proof: in the paid `assets` journey (`--assets codex --hero-video`) the page must show the loop in its hero at 390 and 1280, light and dark, with `metrics.json` recording it playing with the still as poster; the harness cannot emulate `prefers-reduced-motion`, so the still a reduced-motion reader sees is proven by the page's own rule (checked live against the rendered CSS in `reduced-motion.json`) plus the still in the markup, and `videos[0].file` must exist beside the page and is copied next to the captures. Nonpaid recapture of a retained run uses `FD_ASSET_SOURCE` as for images. Stubbed-provider coverage in `test/make.test.mjs` uses a deterministic stand-in Higgsfield and the machine's real FFmpeg: preview names the video cost and ceiling, no approval or `CI` makes no video job, the loop file lands beside the still, the page references it with poster and still fallback, and only one video per option is made. `test/clarity.test.mjs` proves an unrelated autoplaying video still fails while the marked loop and a project recording pass.

## Cleanup

The journey stops only its own view process and named browser and removes its own temporary config/profile. Generated HTML, WebP and captures remain in the evidence folders. A failed design can leave its paid images on disk and must not trigger a generation retry.
