# GitHub-rendered README and quality page

## Drive

Run `done-done run readme` from a clean candidate with normal HOME and DONE_DONE_HOME unset. Requires installed `gh-axi`, `chrome-devtools-axi` and network access to GitHub's Markdown API, the version-pinned github-markdown-css stylesheet and badge endpoints. No model call, sign-in flow or paid generation is made. `FD_README_BEFORE=/external/before.md` and `FD_QUALITY_BEFORE=/external/before-quality.md` optionally add historical frames for each page.

The journey renders the real README and the real `docs/quality.md` with GitHub's API, resolves candidate images locally, opens a named isolated chrome-devtools-axi session, and captures each article at 390×844 and 1280×800 in light/dark (README frames `{before,after}-*`, quality frames `quality-{before,after}-*`). The local article layout uses github-markdown-css 5.8.1, not the full github.com navigation shell. The same article is used for before and after. State readbacks check image loading, page overflow, after command-block overflow on the README, and on the quality page that the score chart follows the theme and every row picture loads. It saves whole first-screen and full-article PNGs, GitHub HTML, the stylesheet, state JSON and `steps.json`; finally it stops its owned browser session. Use `magick before-390-light.png after-390-light.png +append comparison-390-light.png` (repeat each cell, and for `quality-`) outside the repo for Main's before | after review.

## Inspect

Look at every 390/1280 light/dark first screen and full article before requesting review, for both pages. On the README the name comes first, then the single outcome line, the animated hero of two real retained options in the Studio, links/badges and the three-command quick start. Device/theme-specific assets must load: the hero is `docs/media/reviewed-pair{,-phone}{,-dark}.gif`, and it is admissible only as the pinned reviewed sample in sample-provenance. The critic illustration under the proof heading is explicitly a formatted excerpt of retained real output, not a shipped interactive critic screen, a new generation or independent review. On the quality page the first screen must answer the question in one sentence and the chart: First Draft scored 8, 8, 7 and 7.5 against 6.5, 6, 6.5 and 3 for the plain prompt on the same model, every number from the retained bake-off cells, with the old-engine numbers below under History.

This proves the README presentation, not generation quality. For the tool itself, separately run the nonpaid `studio` journey on retained outputs (`FD_STUDIO_SOURCE=<two-option-folder> done-done run studio`) or the `landing` journey as the narrowed Checks claim requires. Keep all runtime captures outside the repo and cite only one or two whole run-id-prefixed frames with one narrowed outcome.
